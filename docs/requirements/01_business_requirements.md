# 業務要求仕様書 - KABUtrade

## 1. プロジェクト概要

### 1.1 プロジェクト名
KABUtrade - 株式売買シグナル自動生成・通知システム

### 1.2 プロジェクトの目的
- 株価データの自動取得と解析により、売買タイミングの客観的判断を支援
- 技術的指標に基づく売買シグナルの自動生成
- 投資判断の効率化と感情的な判断の排除
- 相場式投資手法に基づく高度な分析アルゴリズムの実装

### 1.3 対象市場
- 米国株式市場（NYSE、NASDAQ）
- 日本株式市場（東証）

### 1.4 プロジェクトスコープ
- 日本株式市場（東証）および米国株式市場（NYSE/NASDAQ）の銘柄分析
- 複数の技術指標を組み合わせた売買シグナル生成
- 自動メール通知機能
- バックテスト機能による戦略検証

## 3. 機能要求

### 3.1 売買シグナル生成機能
#### 3.1.1 基本シグナル
- **75日線ブレイクアウト**
  - 買いシグナル: 日足が75日線を下から上に抜けて陽線で終わる
  - 売りシグナル: 日足が75日線を上から下に抜けて陰線で終わる

- **連続陰線・陽線**
  - 買いシグナル: 陰線が9日間または13日間連続
  - 売りシグナル: 陽線が9日間または13日間連続

#### 3.1.2 移動平均線シグナル
- **パンパカパン (PPP)**
  - 買いシグナル: 移動平均線が5 < 20 < 60 < 100 < 200 < 300日の順で配置
  - 売りシグナル: 移動平均線が5 > 20 > 60 > 100 > 200 > 300日の順で配置

- **ゴールデンクロス・デッドクロス**
  - 買いシグナル: 25日線が75日線を下から上に抜ける
  - 売りシグナル: 25日線が75日線を上から下に抜ける

#### 3.1.3 相場式投資手法シグナル
- **下半身 (Lower Half)**
  - 買いシグナル: 5日線が上昇トレンドで、前日の日足が5日線より下にあり、当日の陽線が5日線を実体の50%以上突き抜ける
  - 売りシグナル: 逆下半身（反対条件）

- **くちばし (Bird Beak)**
  - 買いシグナル: 5日線と10日線が上昇トレンドで、前日の5日線が10日線より下にあり、当日の5日線が10日線を上抜ける
  - 売りシグナル: 逆くちばし（反対条件）

### 3.2 トレンド判定機能
#### 3.2.1 上昇トレンド判定
- **ケースA**: 5日線 < 20日線の場合、5日線 < 終値であれば上昇トレンドとしてカウント
- **ケースB**: 20日線 < 5日線の場合、20日線上昇かつ20日線 < 終値であれば上昇トレンドとしてカウント
- **ケースC**: 30日線 < 5日線の場合、20日線・30日線上昇かつ30日線 < 終値であれば上昇トレンドとしてカウント

#### 3.2.2 下降トレンド判定
- **ケースD**: 20日線 < 5日線の場合、終値 < 5日線であれば下降トレンドとしてカウント
- **ケースE**: 5日線 < 20日線の場合、20日線下降かつ終値 < 20日線であれば下降トレンドとしてカウント
- **ケースF**: 5日線 < 30日線の場合、20日線・30日線下降かつ終値 < 30日線であれば下降トレンドとしてカウント

### 3.3 通知機能
- **メール通知**
  - シグナル発生時の自動メール送信
  - Google Apps Script経由での通知
  - 通知内容: 銘柄名、シグナル種別、シグナル詳細

### 3.4 データ管理機能
- **データ取得**
  - Yahoo Finance APIからの株価データ取得
  - Alpha Vantage API対応（予備）
  - レート制限対応（リトライ機能、キャッシュ機能）

- **データ保存**
  - CSVファイルによるキャッシュ機能
  - 取得データの永続化

## 4. 非機能要求

### 4.1 性能要求
- **データ取得**: 1銘柄あたり最大3分以内
- **分析処理**: 全銘柄の分析を30分以内に完了
- **通知送信**: シグナル発生から5分以内に通知

### 4.2 可用性要求
- **システム稼働時間**: 平日市場開場前（日本時間8時）に確実に実行
- **障害対応**: API制限やネットワーク障害時の自動リトライ

### 4.3 セキュリティ要求
- **API認証**: 環境変数による認証情報管理
- **データ保護**: 個人情報の適切な取り扱い

### 4.4 保守性要求
- **ログ機能**: 実行ログの記録と保存
- **設定管理**: 銘柄リストの容易な変更
- **テスト機能**: バックテスト機能による戦略検証

## 5. 制約事項

### 5.1 技術的制約
- **API制限**: Yahoo Finance APIのレート制限（1分あたり最大2000リクエスト）
- **データ遅延**: リアルタイムデータではなく、15-20分遅延のデータ使用
- **プラットフォーム**: Python 3.9以上での動作

### 5.2 運用制約
- **実行時間**: 平日のみ実行（土日祝日は市場休場）
- **メンテナンス**: 月1回のシステム点検・更新

### 5.3 法的制約
- **投資助言**: 本システムは投資助言業務ではなく、情報提供のみ
- **責任範囲**: 投資判断は最終的に利用者の責任
