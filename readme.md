# 仕様

この Python コードは、Yahoo Finance API (yfinance) を使用して株価データを取得し、そのデータを基に売買のシグナルを生成するものです。具体的には以下のような処理を行っています。

## パフォーマンス最適化 (2025年実装)

GitHub Actionsの日次ジョブは以下の最適化により、**4-5時間から約6秒に短縮**されました（99%以上の高速化）:

### 実装された最適化
1. **バッチデータ取得** ([get_yahoo_finance.py:68](src/get_stock_data/get_yahoo_finance.py#L68))
   - `yf.download()`で全銘柄を一括取得
   - 従来: 19銘柄を逐次取得（各1秒sleep + API呼び出し時間）
   - 改善後: 1回のAPI呼び出しで全銘柄取得（約3秒）

2. **並列処理** ([main.py:43](src/main.py#L43))
   - `ThreadPoolExecutor`で最大10並列でシグナル処理
   - CPU集約的な計算を並列化して高速化

3. **取得期間の最適化** ([main.py:37](src/main.py#L37))
   - 10年分(3650日)から400日に削減
   - 300日移動平均の計算に必要な最小限のデータのみ取得

### パフォーマンス結果
- **実行時間**: 4-5時間 → 約6秒
- **データ取得**: 約3秒（19銘柄一括）
- **シグナル処理**: 約3秒（並列処理）
- **目標達成**: 毎営業日AM8:00開始 → 9:00前に完了

1. Alpha Vantage の API キーを環境変数から取得します。
2. Alpha Vantage の API を使用して、指定した銘柄（ここでは'SPY'）の日次株価データを取得します。
3. 取得した株価データに対して、移動平均線を計算します。移動平均線の期間は、5, 20, 25, 30, 60, 75, 100, 200 日としています。
4. 陽線と陰線を判定します。陽線は終値が始値より高い日、陰線は終値が始値より低い日を指します。
5. 以下の条件に基づいて売買のシグナルを生成します。

### 前提条件

- 上昇トレンドが 3 か月以上続いていることを判定します。
  - ケース A: (5 日移動平均線 < 20 日移動平均線)の場合
    - (5 日移動平均線 < 終値)であれば上昇トレンドと判定し、日数をカウント
  - ケース B: (20 日移動平均線 < 5 日移動平均線)の場合
    - 20 日移動平均線が上昇、かつ、(20 日移動平均線 < 終値)であれば上昇トレンドと判定し、日数をカウント
  - ケース C: (30 日移動平均線 < 5 日移動平均線)の場合
    - 20 日移動平均線および 30 日移動平均線が上昇、かつ、(30 日移動平均線 < 終値)であれば上昇トレンドと判定し日数をカウント
- 上昇トレンドにおける例外処理

  - 下記の条件が成立する場合は、上昇トレンドの日数カウント処理を一時中断する
  - (30 日移動平均線 < 5 日移動平均線)の場合
  - 20 日移動平均線が下降、かつ、30 日移動平均線が上昇、かつ、(長期移動平均線 < 終値)である状態
    以上の条件で日数をカウントし、60 カウントが成立して以降、条件が成立する間は上昇トレンドが形成されていると判定します。

- 下降トレンドの場合が 3 か月以上続いていることを判定します。

  - ケース D: (20 日移動平均線 < 5 日移動平均線)の場合
    - (終値 < 5 日移動平均線)であれば下降トレンドと判定し、日数をカウント
  - ケース E: (5 日移動平均線 < 20 日移動平均線)の場合
    - 20 日移動平均線が下降、かつ、(終値 < 20 日移動平均線)であれば下降トレンドと判定し、日数をカウント
  - ケース F: (5 日移動平均線 < 30 日移動平均線)の場合
    - 20 日移動平均線および 30 日移動平均線が下降、かつ、(終値 < 30 日移動平均線)であれば下降トレンドと判定し、日数をカウント

- 下降トレンドにおける例外処理
  - 下記の条件が成立する場合は、下降トレンドの日数カウント処理を一時中断する
  - (5 日移動平均線 < 30 日移動平均線)の場合
    - 20 日移動平均線が上昇、かつ、30 日移動平均線が下降、かつ、(終値 < 30 日移動平均線)である状態

以上の条件で日数をカウントし、60 カウントが成立して以降、条件が成立する間は下降トレンドが形成されていると判定します。

### シグナルの生成

- 買いシグナル：日足が 75 日線を下から上に抜けて陽線で終わる、または陰線が 9 日間または 13 日間連続する
- 売りシグナル：日足が 75 日線を上から下に抜けて陰線で終わる、または陽線が 9 日間または 13 日間連続する
- 移動平均線が 5, 20, 60, 100, 200, 30 日の順番で高い場合は買いシグナル、逆に低い場合は売りシグナルとします。
- ゴールデンクロス（短期の移動平均線が長期の移動平均線を下から上に抜ける現象）が発生した場合は買いシグナル、デッドクロス（短期の移動平均線が長期の移動平均線を上から下に抜ける現象）が発生した場合は売りシグナルとします。
- 下半身：買いシグナルシグナル 5 日線が上昇トレンドで、前日の日足線が 5 日線より下にあり、かつ、当日の日足線が陽線で 5 日線を実体の半分以上突き抜けていれば、買いシグナルとします。逆を逆下半身として売りシグナルとします。
- くちばし:5 日線と 10 日線が上昇トレンドで、前日の 5 日線が 10 日線より下にあり、かつ、当日の 5 日線が 10 日線を上抜けていれば、買いシグナルとします。逆を売りシグナルとします。

6. 最新の日付でのシグナルを出力します。ゴールデンクロスもデッドクロスもない場合、連続上昇日数または連続下落日数に基づくシグナル、移動平均に基づくシグナルをチェックします。
7. 最後に、株価と移動平均線、売買のシグナルをプロットします。
   なお、このコードでは実際の売買注文は行わず、シグナルの生成だけを行っています。

## 環境変数

AlphaVantage API キーを環境変数として設定する必要があります。GitHub Actions では、Secrets を使用して環境変数を設定できます。

以下の手順で設定を行ってください：

GitHub リポジトリの設定ページに移動します。
左側のメニューから"Secrets"を選択します。
"New repository secret"をクリックします。
"Name"フィールドに ALPHAVANTAGE_API_KEY と入力し、"Value"フィールドに API キーを入力します。
"Add secret"をクリックします。
これで、API キーはリポジトリの Secrets に保存され、ワークフローから参照できます。

次に、ワークフローファイル（daily_exec.yaml）を更新して、この Secret を環境変数として使用します：

```
jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v2

      - name: Set up Python
        uses: actions/setup-python@v2
        with:
          python-version: "3.x"

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r ${{ github.workspace }}/requirements.txt

      - name: Run script
        run: python src/main.py
        env:
          ALPHAVANTAGE_API_KEY: ${{ secrets.ALPHAVANTAGE_API_KEY }}
```
